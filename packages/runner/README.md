# Tea Runner

`@tea/runner` contains the shared ACP runtime and the `tea-runner`
executable. A Runner is a cloud execution service even when its process runs
on an enterprise server or in a container. One TOML file can register several
logical Runner entries; the executable maintains them over one Center
WebSocket.

## Register

No package installation is required. The command generated by Tea Desktop uses
`npx` to fetch the published package and is safe to paste as one shell command:

```sh
npx --yes @tea/runner register --center-url 'https://center.example.com' --token '<registration-token>' --install-service
```

With `--install-service`, the command writes the configuration and starts the
Runner in the background. The command prints the log location after starting.
To run in the current terminal instead, omit `--install-service`:

```sh
npx --yes @tea/runner register --center-url 'https://center.example.com' --token '<registration-token>'
```

This mode stays attached to the terminal and prints human-readable lifecycle,
connection, reconnect, and execution errors to stderr. Press `Ctrl-C` to ask
the Runner to drain active conversations before exiting. To start an already
written configuration as a background process, run
`npx --yes @tea/runner install-service [/path/to/runner.toml]`.

Service logs are written to `runner.log` under the platform cache directory:

- macOS: `~/Library/Caches/tea/runner/runner.log` (or `$XDG_CACHE_HOME`)
- Linux: `~/.cache/tea/runner/runner.log` (or `$XDG_CACHE_HOME`)
- Windows: `%LOCALAPPDATA%\tea\runner\runner.log`

Set `TEA_RUNNER_CACHE_DIR` to use an explicit cache directory. The log
directory is created with mode `0700` and the log file with mode `0600` where
the operating system supports these permissions. Tokens and credentials are
never included in Runner log fields.

## Configuration

The default file is `$XDG_CONFIG_HOME/tea/runner.toml` (or
`~/.config/tea/runner.toml`). A minimal file is:

```toml
center_url = "https://center.example.com"
workspace_root = "/tmp/tea-runner"
state_dir = "/var/lib/tea-runner"

[[runners]]
local_key = "host-linux"
name = "build-host"
token = "<registration-token>"
tags = ["linux", "acp"]
limit = 5
```

Add another `[[runners]]` entry to register another logical Runner on the same
host. Names may repeat. `tags` is required and must contain unique non-empty
values. `limit` defaults to 5, while `concurrent` defaults to the number of
entries. Center can update limits, tags, and concurrency over the existing
connection; accepted updates are written back to this file and reloaded.

If `workspace_root` is omitted, the Runner uses a private temporary root. Each
conversation gets an isolated directory below it. `state_dir` stores the
ordered event spool and local runner state; use a private directory with mode
`0700` and keep the TOML file at mode `0600`.

## Runtime execution

The Runner starts the ACP executable configured in `agents`. Runtime, provider,
model, permission mode, and Center plugin references arrive with each command.
Provider credentials and plugin secrets remain in Center. A missing capability
is reported as a structured execution error instead of silently selecting a
different Runner.

The package includes the official Claude and Codex ACP agents by default. If
`agents` is omitted, the Runner uses `external.claude` with
`claude-agent-acp` and `external.codex` with `codex-acp`. Existing TOML files
without an `agents` section therefore run the same real ACP agents; they do not
fall back to an echo implementation. Add an `agents` section only when a
deployment intentionally replaces or extends those executables.

When the WebSocket disconnects, active ACP tasks continue locally. Events are
spooled and replayed after reconnect; disk-full conditions block and retry so
events cannot be dropped. `stop()` waits for active work to drain. Use the
explicit `--force` run option only when terminating work is acceptable.

## Container deployment

Mount the configuration as a private secret and provide writable state and
workspace directories:

```sh
docker build -f packages/runner/Dockerfile -t tea-runner .
docker run --rm \
  --read-only \
  --tmpfs /tmp \
  -v /etc/tea/runner.toml:/etc/tea/runner.toml:ro \
  -v tea-runner-state:/var/lib/tea-runner \
  tea-runner /etc/tea/runner.toml
```

Center remains responsible for authentication, token revocation, tag routing,
cloud conversation history, tenant plugins, and access control.
